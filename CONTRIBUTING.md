# Contributing

Thanks for considering a contribution.

## Proposing a change

- For a bug, describe the command you ran, the result you expected, and the result you saw. Do not include private repository contents or secrets.
- For a new check, explain the user need and the filename or directory patterns it should recognize.
- Keep the default scan read-only and avoid adding third-party dependencies without a clear reason.

## Making a change

1. Create a focused branch for your change.
2. Update the documentation when behavior or supported checks change.
3. Before opening a pull request, run the CLI against a small sample directory and review the Markdown output.
4. Summarize the change and any limitations in the pull request.

The project is a small utility, so concise changes with clear behavior are easiest to review.
